# Wayfinder 地图：协议无关的双向 RPC

Label: wayfinder:map
Status: open

## 目的地

为 `packages/remote` 产出决策完备的协议无关双向 RPC 规范与实施路线，其中包含准确的公开 TypeScript 接口、类型、字符串枚举、使用示例、行为保证和验证契约。每项公开声明都必须能追溯到具体的使用者任务，并通过面向使用者的场景验收；实施阶段所需的产品或架构决策不能再有任何隐含项。

## 说明

- 权威领域词汇以根目录的 `CONTEXT.md` 为准。
- 每个决策会话都应查阅 `grilling`、`domain-modeling`、`codebase-design` 和 `ponytail`；原型票还应使用 `prototype`，研究票应使用 `research`。
- 先从使用者工作流设计，再推导公开声明。人体工学属于正确性的一部分，而不是实现完成后的润色工作。
- `Connector` 主动建立一个远程关系；`Acceptor` 被动管理多个已接受的对等端。连接建立后，RPC 能力保持对称。
- 暴露服务和获取代理都不要求物理连接已经存在。断线时发起的单对等端调用会被拒绝，而不会进入隐藏的离线队列。
- `Acceptor.peers` 是普通的只读快照数组。批量代理通过 `Acceptor.resolveAll()` 获取；每次批量方法调用都会对目标对等端取快照，并独立报告每个结果。
- 远程服务类型从 `@husky-di/core` 的服务类型推导。只有显式选择、以字符串命名的普通方法可以被远程调用；同步返回值会变为 Promise。
- 稳定的线上名称使用字符串。字符串服务标识符可以默认使用自身名称；构造器和 Symbol 标识符必须显式提供线上名称。
- 有限闭合集合使用 TypeScript 字符串枚举。
- 公开接口使用 ECMAScript 能力以及 `AbortSignal` 等跨运行时 Web Platform 原语；Node 或浏览器专属的传输类型不能穿过 RPC 接口。
- 实现面向 TypeScript/JavaScript 对等端，但规范化消息契约应当便于其他语言实现。
- 第一版实现一元调用，并为未来流式调用保留兼容接缝。ACK、交付重传、业务重试和瞬时重连都必须形成明确决策。
- 身份认证由传输层或集成层提供。RPC 核心仍必须安全拒绝畸形消息和未知消息。
- 只要两端进程仍然存活，逻辑会话就可以跨越瞬时物理断线；进程重启会结束会话。
- 公开行为最终必须写入 `packages/remote/docs/SPECIFICATION.md`，并在同一实现变更中由 `packages/remote/tests/specification.test.ts` 覆盖。

## 已有决策

### 人体工学验收原则

- 先写调用代码，后定 interface：每个 public member 必须由一个具体使用场景证明其必要性。
- 常见路径最短：普通的一元调用、服务暴露、单 peer 调用和全部 peer 批量调用不应要求使用者理解 transport、frame、registry 或 session 恢复细节。
- 高级能力渐进暴露：重连、重试、ACK、codec 和未来 streaming 只在相关场景中出现，不污染默认调用路径。
- 名称和结构遵循使用者心智模型：`Connector` 主动连接，`Acceptor` 被动接收；连接后双方都通过同一种 `RpcPeer` 模型调用与暴露服务。只有拓扑确实不对称的地方才使用不同 API。
- 状态、错误和所有权必须可发现：断线时何时失败、谁负责 `dispose()`、批量调用如何表达部分失败，都要能从类型、命名和返回值看出，不能依赖隐藏上下文或隐式队列。
- 优先复用现有词汇和平台原语；不为假想扩展增加 wrapper、options 或透传方法。任何 public member 都必须通过删除测试：删除后若没有把必要复杂度转嫁给使用者，就不应存在。

## 尚未明确

- 最终规范的需求编号和章节结构；它们会在公开接口与线上行为收敛后变得清晰。
- 具体的实施票和文件拆分；它们会在外部接缝和内部接缝确定后形成。
- 哪些已解决的权衡需要 ADR，而不应只记录在规范中。

## 不在范围内

- 本次 Wayfinder 工作中的生产实现；只有决策地图抵达目的地后才进入实施阶段。
- WebSocket、TCP、MessagePort、WebTransport 或其他具体协议的内置生产 adapter。范围内只有协议无关接缝和用于验证的内存 adapter。
- 任一对等端进程重启后的持久化会话恢复。
- 第一版中的流式 RPC 实现；范围内只有保留兼容接缝。
- 身份认证、授权策略、限流和服务发现。
- 发布非 TypeScript SDK，或承诺与某个现有第三方 RPC 标准保持线上兼容。
- 对等端路由查询语言或隐式环境路由。第一版只需要显式单对等端调用，以及面向全部当前对等端的批量调用。
